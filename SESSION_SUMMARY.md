# Session Summary — Glioma Cox Survival Pipeline & 4-Gene Risk Score App

**Date:** 2026-08-09
**Project:** IDH-mutant glioma transcriptomic biomarkers of overall survival (Oldham Lab, UCSF Dept. of Neurological Surgery)

---

## 1. Goal

Refactor a duplicated, per-cohort genome-wide Cox proportional-hazards survival scan (Gravendeel, Kamoun, Weller, CGGA glioma expression cohorts) into a single reusable pipeline, validate four candidate prognostic genes (**DEPDC1, GREM1, PLD1, TMEM165**) across cohorts, and build a standalone research tool that computes a prognostic risk score from the four genes.

---

## 2. Reusable Cox pipeline

Built two R scripts as the shared statistical core, later reused unchanged across every downstream analysis:

- **`cox_survival_pipeline.R`** — `run_cox_survival_pipeline()`, a single parameterized function per cohort covering: IDH1-mutant filter → SampleNetwork-style Z.K outlier removal (Z.K < -4) → log2 transform → quantile normalization → ComBat batch correction → Affymetrix probe→gene mapping (`hgu133plus2.db`) → vectorized per-probe Cox regression → FDR (`qvalue`, BH fallback). Also exposes standalone helpers (`compute_ZK`, `remove_ZK_outliers`, `log2_transform_matrix`, `map_probes_to_genes`, `cox_scan`, `fdr_correct`, `collapse_to_gene_level`, `pool_singleton_batches`) so downstream scripts reuse the same logic instead of re-implementing it.
- **`combined_cohort_pipeline.R`** — `run_combined_cohort_pipeline()`, pools multiple cohorts into one validation cohort (combine raw matrices → log2 → pooled Z.K outlier removal + quantile norm → ComBat by **cohort-of-origin** → Cox scan + FDR), built entirely on the same shared helpers.
- Both support an optional **gene-level collapse** step (`collapse_method`: `"min_p"`, `"max_p"`, or `"fisher"`) run *before* FDR correction, since collapsing after FDR dilutes real signal across a gene's multiple probes. `min_p` carries an explicit bias warning (best-of-N selection inflates significance) — this was already documented as invalid-for-primary-use in the project's own `regression_analysis_genelevel_significancebased.r`.
- Synthetic end-to-end tests (`test_synthetic_pipeline.R`, `test_synthetic_combined_pipeline.R`) validate every step, including a genuine Z.K-outlier-detection check (fixed once — initial synthetic "normal" samples had no real inter-sample correlation structure, so injected outliers went undetected until a shared per-probe baseline was added).

## 3. Per-cohort data inspection (before trusting any numbers)

Inspected real metadata/expression for all four cohorts rather than assuming column names/units:

- **Gravendeel (GSE16011):** orphan sample `O_3_IDH1_66` in expression but not metadata (dropped); `Time`/`Event` clean; `IDH1_Mut` 100% mutant (already pre-filtered).
- **Kamoun (EMTAB3892):** `Time` column mixed plain decimals with `"105/12"`-style month fractions — required a dedicated `parse_time_months_or_years()` parser (ported from the project's existing `Regression Analysis.r`).
- **Weller (GSE61374):** no IDH mutation column at all — user confirmed to treat all samples as pre-filtered IDH-mutant.
- **CGGA:** required real detective work — multiple near-duplicate candidate file pairs with mismatched sample IDs (110/693 overlap on the wrong pairing). Eventually found the correct working pair (`CGGA DS3 693 Analyte Data Oct 39.csv` + `CGGA DS3 693 Sample Attributes Oct 39 2023.csv`, 307/307 overlap) by tracing which files an existing project script (`gradeadjustedcode.r`) successfully used. Raw RNA-seq counts (range 0–14.2M) required CPM + log2(CPM+1) rather than quantile normalization.
- All raw expression matrices were confirmed **linear-scale, not log2** — a log2 transform step was added to the pipeline (toggleable, since CGGA needed CPM+log2 instead of the arrays' quantile+log2 path).

## 4. Per-cohort and pooled validation runs

- Ran Gravendeel, Kamoun, Weller independently and pooled (ComBat by cohort-of-origin). Watchlist genes did not clear genome-wide FDR at the probe level in any run (42,548 tests badly dilutes signal).
- Added gene-level collapsing (`min_p`) to correct for this — reduced the pooled test count to 19,707 genes; q-values improved substantially (0.9999 → ~0.36–0.38) but still didn't clear q<0.05.
- Ran a `max_p` ("worst probe") control as a sanity check: DEPDC1/PLD1/TMEM165 signal collapsed almost entirely (as expected if it's genuine probe-specific signal, not noise); GREM1 (only 2 probes) held up better, consistent with a weaker "worst-of-N" selection effect on fewer probes.

## 5. CGGA discovery analysis — the numbers that mattered

Found a pre-existing, more comprehensive analysis already on disk (`master_gene_evidence_table.csv` / `presentation_gene_summary.csv`, generated by `gene_evidencetable.r`), merging discovery Cox (both collapse methods), OLS, **CGGA validation Cox**, and grade-adjusted Cox (with 1p/19q) results per gene. In the `cgga_cox_*` columns, **all four watchlist genes clear FDR**:

| Gene | coef (log HR, z-scored) | HR | p | q |
|---|---|---|---|---|
| DEPDC1 | 0.3910 | 1.478 | 3.65×10⁻¹² | 4.47×10⁻¹⁰ |
| TMEM165 | 0.4970 | 1.644 | 9.29×10⁻⁷ | 1.32×10⁻⁵ |
| GREM1 | 0.2063 | 1.229 | 7.67×10⁻³ | 1.60×10⁻² |
| PLD1 | 0.2186 | 1.244 | 1.45×10⁻² | 2.57×10⁻² |

- **Verified the coefficient scale empirically** (not just by inspection): independently re-fit the same univariate Cox models on the properly-aligned CGGA cohort (CPM → log2(CPM+1) → z-score, n=307/288 complete cases) and got near-identical coefficients (DEPDC1 0.3944 vs 0.3910, PLD1 0.2192 vs 0.2186, etc.) — confirmed the master table's coefficients are z-scored, matching this pipeline's convention.
- **7,966 genes** clear `cgga_cox_q < 0.05` in the master table — an exact match to the count cited in the QBI deck, corroborating it as the deck's real source.
- SE per gene was back-derived exactly via the Wald relationship (`se = |coef| / qnorm(1 - p/2)`), since the source table didn't store it directly.
- Grade-adjusted results (`grade_adjusted_cox_693.csv`) map onto the deck's Category framework: DEPDC1 and TMEM165/PLD1 remain significant after adjusting for tumor grade ("grade-independent"), GREM1 does not ("grade-associated") — matching Category 1/3 vs Category 2.

## 6. Pooled-validation cross-platform check

Computed a linear predictor for the pooled Gravendeel+Kamoun+Weller cohort (Affymetrix, n=272) using the CGGA-fit coefficients, **z-scoring each cohort against its own distribution** (not importing CGGA's RNA-seq mean/SD onto a different platform's array intensities — a deliberate methodological call, not an oversight). Tertile split:

| Group | n | Events | Median survival |
|---|---|---|---|
| Low | 91 | 55 | 6.3 yr |
| Intermediate | 90 | 44 | 6.7 yr |
| High | 91 | 46 | 4.9 yr |

**Log-rank p = 0.00058.** Caveat surfaced explicitly: most of the separation is High-vs-rest (13.9 of the 14.9 χ² statistic) rather than a uniform 3-way gradient.

## 7. The risk-score calculator app

Built **`app/glioma_risk_score.html`** — a standalone, single-file HTML/JS research tool (no server, works fully offline). Delivered in two passes:

**v1:**
- 4 gene input fields (CPM/TPM), log2+z-score against CGGA's own mean/SD, tertile cutoffs computed on the CGGA cohort itself (**-0.353 / +0.411**), risk chip, per-gene contribution breakdown, gene annotation cards (Category/program/evidence_score), embedded Chart.js Kaplan-Meier chart (real extracted `survfit()` step data, not an approximation), collapsible methodology note, non-clinical-use disclaimer.
- Validated against 3 real CGGA samples with known outcomes: a long survivor (alive at 8.4 yr) scored **-2.313 / Low**; a short survivor (died at 0.84 yr) scored **+2.274 / High**; a moderate-outcome sample (died at 4.2 yr) scored **-0.095 / Intermediate** — all as expected.

**v2 (8 sequential enhancements, each re-verified against the same 3 samples):**
1. Chart.js inlined (206KB UMD build embedded directly) — removes the CDN dependency entirely; confirmed via network-log/static-analysis that the file makes zero external requests.
2. Per-field input validation (blank/non-numeric/negative rejected with specific inline messages); Calculate button disabled until all 4 fields are valid.
3. Out-of-range warning: flags any gene with |z|>3 (outside CGGA's observed range) by name, without blocking the calculation.
4. Score uncertainty: 95% CI propagated from each gene's Wald-derived SE (`Var(score) = Σ(z·SE)²`, independence assumption stated explicitly in the methodology note).
5. Reference ranges (10th–90th percentile in CGGA) shown beside each input field.
6. A second chart: the CGGA cohort's own linear-predictor histogram, with the two tertile cutoffs and the current sample marked — replaces the bare risk chip as the primary visual (chip kept as a secondary at-a-glance label).
7. CSV batch mode: upload a CSV of samples, score all rows through the *same* `scoreSample()` function used in single-sample mode (refactored into a shared pure function first), render a results table, download results as CSV.
8. A separate "About this tool" collapsible section (Oldham Lab / UCSF Dept. of Neurological Surgery, data provenance, project context) written to stand alone for a reader with no other context.

All 3 sanity-check scores (-2.313 / +2.274 / -0.095) were re-confirmed identical after every one of the 9 verification passes (8 features + final check). Final file: 999 lines, 254KB, zero console errors, fully offline-capable.

## Open items / caveats worth remembering

- The pooled-validation tertile split separates survival overall (p=0.00058) but is really a "High vs. rest" signal, not a clean 3-way gradient — stated explicitly in the app.
- The app's uncertainty interval assumes independence across the 4 genes' contributions; genes may in fact be correlated, so the true interval could differ.
- CGGA discovery numbers rely on `master_gene_evidence_table.csv`, whose exact generating script for the `cgga_cox_*` columns couldn't be located on disk — the coefficient *scale* was independently re-verified by re-fitting the model directly, but the exact upstream pipeline (n=307 vs. a possible sample subset) wasn't fully traced beyond that.
